# Matrices and cases Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a real equation grid to `papercut/math`: a `Grid` node, `Math::matrix()` and `Math::cases()` builders, MathML `mtable` reading, and MathML, Word OMML and text writers.

**Architecture:** One new node, `Grid`, lays cells out like TeX's `matrix` and centres itself on the math axis. A matrix is a `Fenced` around a `Grid`; `cases` is `Fenced('{', '', Grid)`. The MathML reader builds a `Grid` from `mtable`, replacing today's flat-row approximation. Core, docx and laravel need no new API: formulas already flow through `papercut/math`.

**Tech Stack:** PHP 8.4, PHPUnit, PHPStan. Work in the worktree `~/work/olc/papercut-matrices` (branch `matrices`); the package is `packages/math`, tests run with `vendor/bin/phpunit` from there.

**Spec:** `docs/superpowers/specs/2026-11-15-matrices-design.md` (read it first; this plan only records what it leaves to the implementer).

## Global Constraints

- PHP `^8.4` floor. Local php is 8.5, CI also runs 8.4: run each suite with `php@8.4` too before the final commit (Task 5).
- Output for formulas without a table is byte-identical: every existing snapshot under `tests/snapshots/{mathml,omml}` for existing fixtures stays unchanged.
- `Grid` is a public node class like `Fenced`; only its `layout()` and `children()` carry the `@internal` docblock the other nodes use. `ArchitectureTest`'s `INTERNAL` list does not change.
- The reader's only limit stays `MAX_DEPTH = 256`; the table keeps counting two levels toward it. No new cell or node caps.
- Notes use `MathNote(NoteLevel::Approximated, <element>, '<attribute> is not drawn', <where>)`, deduped by the reader's existing `note($key, ...)` with key `"<element>/<attribute>"`.
- A grid never produces a newline in `TextWriter` output.
- No new Blade tags or markup syntax; matrices reach markup and Blade through MathML `mtable`.
- Commits: end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; no session links.

## Review Focus

Input classes the spec implies but the obvious tests would miss, most likely first. Each has its test in the task named:

1. **Ragged and empty tables from MathML:** `<mtable/>`, an `mtr` with no `mtd`, an `mtd` with no children, rows of unequal length. No crash, no stray note, empty cells padded. (Task 4)
2. **A big grid:** 60 rows by 60 columns lays out fast and without quadratic behaviour. (Task 1)
3. **Grids nested** in a cell, inside a `Fraction`, a `Scripts` base, and a `Fenced` inside a cell. Layout and all three writers cope. (Tasks 1 and 3)
4. **Garbage attribute values:** `columnalign="decimalpoint foo"`, `columnalign=""`, more tokens than columns, `rowalign="none"`, `rowspan="abc"`, `displaystyle="maybe"`. Defaults apply, no crash. (Task 4)
5. **Invalid UTF-8 and odd strings in cells** through the builders, and Wiris's `<mtd><mo>&nbsp;</mo></mtd>` filler cells through the reader. Scrubbed with a note; no crash. (Tasks 2 and 4)

- [ ] **Step 3: Implement `Grid`** in `src/Node/Grid.php`, with the signature above. Constructor: validate alignments (throw `InvalidArgumentException` naming the bad value and the allowed ones), pad every row on the right with `new Row([])` to the widest row, expand `$columnAlign` to one entry per column (repeat the last; `center` when empty). `layout(Context $c)` algorithm:
  1. Cell context is `$c->withDisplay($this->display)`; lay each cell out once.
  2. Column width is the widest cell; column x offsets are cumulative widths plus `1 em` (`$c->size()`) gaps; a cell sits at its column's x plus `0`, `(w - cw)/2` or `w - cw` for left, center, right.
  3. Row ascent `A_i` and descent `D_i` are the maxima of its cells' ascents and descents. Row baselines: `b_0 = 0`, `b_i = b_{i-1} + max(1.2 * em, D_{i-1} + A_i + 0.1 * em)`. No struts.
  4. Cell baseline within its row: `baseline` → `b_i`; `top` → `b_i - A_i + cell.ascent`; `bottom` → `b_i + D_i - cell.descent`; `center` → `b_i + ((D_i - A_i) - (cell.descent - cell.ascent)) / 2`; `axis` → `b_i - axis + (cell.ascent - cell.descent) / 2`.
  5. Grid top is `-A_0`, bottom is `b_last + D_last`; shift every placement by `-axis - (top + bottom) / 2` so the whole grid centres on the axis; return a `Box` with `width`, `ascent = H/2 + axis`, `descent = H/2 - axis`.
  6. Empty grid (no rows or no cells): return `new Box()`.
