# PDF/A (archival PDF) for 1.0

Branch `pdfa` (worklog, local), started from `tagged-pdf` (ebe7da2), so PDF/A level "a" can build on tagging.
Background: the 2026-11-01 spike (veraPDF 1.30.3, `enablePdfA` on every example and the stress cases): PDF/A-2b/2u
pass everything (opacity, alpha PNG, SVG gradients, QR, imported pages) once php-pdf PR #53 fixes link `/F 4` and
XMP-from-`/Info`. PDF/A-1b also fails on transparency (6.4-2 SMask, 6.4-5/6 CA/ca).

**Dependency.** Same as tagged-pdf: php-pdf with PR #53. Dev uses the UNCOMMITTED Composer path override in
`packages/core/composer.json` (`repositories.php-pdf-fork` → `~/work/olc/php-pdf-pr53`, faked as 1.99.0). Never
commit it: stage files explicitly, never `git add -A` / `git commit -a`. `enablePdfA()` / `PdfAConfig` exist in
released php-pdf already, so no soft fallback is needed; only validation needs #53.

## Decisions

- Public API: a string-backed enum `Papercut\Export\PdfA` with cases `A1b = '1b'`, `A2b = '2b'`, `A2u = '2u'`,
  `A2a = '2a'`, `A3b = '3b'`, `A3u = '3u'`, `A3a = '3a'`, and `new PdfOptions(pdfA: PdfA::A2u)` (default null = not
  PDF/A), `withPdfA(?PdfA)`, `pdfA(): ?PdfA`. `withEncryption()` / `withTagged()` keep it. Docs recommend `A2u`.
- Level "a" (`A2a`, `A3a`) turns tagging on: same structure tree, same title/lang precondition as `tagged: true`,
  and PDF/UA-1 identification too (php-pdf puts pdfuaid in the PDF/A packet). `tagged: true` with a "b"/"u" level
  is allowed (PDF/A-2u + PDF/UA-1).
- PDF/A with encryption throws `InvalidArgumentException` before rendering, naming both options (php-pdf would throw
  a LogicException mid-render otherwise).
- Bundle an sRGB profile at `packages/core/resources/icc/sRGB2014.icc` (copied from php-pdf's
  `resources/icc/sRGB2014.icc`; ICC's sRGB2014 licence allows redistribution) with a `NOTICE.md` entry, rather
  than reaching into php-pdf's package files. `PdfAConfig` gets the meta's title, author and lang.
- PDF/A-1 can't hold object streams or transparency. In part 1, tagged renders skip `useObjectStreams()`; any
  transparency (opacity < 1, an image with alpha, an SVG with opacity or soft masks) throws a Papercut exception
  that names the element where possible and suggests `PdfA::A2b`. Pages imported from PDFs (templates, `PdfPage`)
  are not inspected: documented.
- Call order in `PhpPdfBackend::render()`: `enablePdfA()` before `useObjectStreams()` (enablePdfA sets the header
  to 1.4; useObjectStreams raises it to 1.5, which PDF/A-2/3 allow) and before any `encrypt()`.
- `Backend::render()` gains the PDF/A level (Backend is `@internal`), next to `$tagged`.
- Laravel: `papercut.pdfa` config (null or '1b'/'2b'/'2u'/'2a'/'3b'/'3u'/'3a', validated like `papercut.tagged`) and
  `PendingDocument::pdfA(PdfA|string|null)`.
- Not promised: ZUGFeRD/Factur-X (php-pdf's attachFile has no AFRelationship); part 3 is offered only because some
  archives demand it, Papercut attaches no files. Word and HTML exports ignore the option.

## Tasks (sequential; each: TDD, full core suite + phpstan green, one commit, no Claude-Session trailer)

1. **Option and plumbing.** `PdfA` enum, `PdfOptions(pdfA:)` + accessors, `Backend::render()` parameter, ICC
   resource + NOTICE, `enablePdfA()` wiring in `PhpPdfBackend`, "a" levels imply tagging (precondition included),
   encryption conflict throws early, part 1 skips object streams. Tests read the output back: header version,
   `/OutputIntents` with the ICC stream, XMP `pdfaid:part`/`conformance` (and `pdfuaid:part` for "a" and for
   tagged + "u"), Info/XMP title match. Untagged non-PDF/A GoldenBytesTest stays byte-identical.
2. **PDF/A-1 transparency check.** Throw as decided above; tests per source of transparency, and that part 2
   allows the same documents.
3. **Laravel.** Config key, `PendingDocument::pdfA()`, validation, tests mirroring the tagged ones.
4. **veraPDF in CI.** Generalize `packages/core/tools/verapdf-ua1.php` into `verapdf.php <flavour> <dir> [report]`
   (keep the UA-1 jobs working) and the render script into one that takes the options (tagged, PDF/A level).
   Core and Laravel CI jobs: every example as PDF/A-2u, and as PDF/A-2a (tagged) validated against both 2a and ua1;
   gated on `TaggingSupport::missing()` like the tagged jobs, because validation needs #53. Local runs must show
   every core and Laravel example compliant; also check one transparency-free example as 1b and 3u by hand.
5. **Docs.** `site/src/guide/pdfa.md` (+ sidebar, link from the accessibility page): what PDF/A is for, which level
   to pick (2u by default, 2a with tagging, 1b only when an archive demands it), rules (no encryption, no
   transparency in part 1, imported PDF pages must comply themselves, signing after rendering must use an
   incremental update, merging breaks conformance), `PdfOptions` docs, Laravel config, CHANGELOG entry.
6. **Final review** (Opus) of the branch, fixes; condense later at release time with tagged-pdf.

At release (with tagged-pdf): drop the override, require the php-pdf release with #53, run both veraPDF jobs.
